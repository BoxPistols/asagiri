## Color system architecture (v3)

`_Color.scss` is organized in four layers:

1. **Reference (`--ref-*`)** — raw tonal palettes (`primary-0..100`, `neutral-0..100`,
   per-hue 4/6/8 anchors for functional colors). Never consumed directly by
   components. Light/dark invariant.
2. **System (`--color-*`)** — semantic tokens. Components consume **only these**.
   Light and dark modes remap system tokens to different reference values.
3. **Component (`--comp-*`)** — optional per-component aliases (defined in each
   component's SCSS, not in `_Color.scss`).
4. **Legacy aliases** — preserved for backward compatibility; new code should
   not use these.

### Brand

| Token | Role |
| --- | --- |
| `--color-primary` | hsla(191, 47%, 53%) — Moonstone cyan; brand core |
| `--color-primary-dark` / `--color-primary-light` | −15% / +15% lightness |
| `--color-on-primary` | Foreground color guaranteed to read on `--color-primary` |
| `--color-primary-container` | `color-mix(primary 18%, surface)` — tonal surface |
| `--color-on-primary-container` | Readable text on the container |
| `--color-secondary` | hsla(224, 23%, 44%) — slate, complementary |

HSLA parts are individually addressable (`--primary-h`, `--primary-s`, `--primary-l`,
`--primary-alpha`), so `--primary-l` gets rewritten to `62%` in dark mode and every
derived color (`light`, `dark`, container) follows automatically.

### Functional palette

`success`, `warning`, `danger`, `info`, `accent`, `elegant` — each with a base,
`-dark`, `-light`, `-bg`, `-bg-dark`, and `-on-*` (foreground) variant.

- `--color-*-bg` — `color-mix(semantic 15%, transparent)`. Use for callout box
  backgrounds; auto-remaps to dark mode because the underlying semantic token
  itself remaps.
- `--color-*-bg-dark` — stronger 30% tint for critical alerts / heroes.
- `--color-on-*` — the foreground color that reads on the semantic background.

### Surface hierarchy (MD3 tonal elevation)

| Token | Role |
| --- | --- |
| `--color-bg` | Page background |
| `--color-surface` | Default card / sheet |
| `--color-surface-1` … `--color-surface-5` | Ascending tonal-lift layers |
| `--color-surface-variant` | Alt surface for code / inline blocks |
| `--color-surface-inverse` / `--color-on-surface-inverse` | Inverse pair (e.g. toasts) |
| `--color-scrim` | Modal backdrop — `color-mix(black 48%, transparent)` |

### Borders

| Token | Alpha |
| --- | --- |
| `--color-border-subtle` | 8 % (light) / 6 % (dark) |
| `--color-border` | 14 % / 12 % |
| `--color-border-strong` | 24 % / 22 % |
| `--color-border-focus` | `--color-primary` |

### Text

| Token | Role |
| --- | --- |
| `--color-text-primary` | Body text |
| `--color-text-secondary` | Meta, helper text |
| `--color-text-tertiary` | Captions, tags, disabled states |
| `--color-text-disabled` | `color-mix(primary 38%, transparent)` |
| `--color-text-on-brand` | White-ish foreground for branded surfaces |
| `--color-text-link` / `-hover` / `-visited` | Hyperlinks |
| `--color-text-code` | Monospaced / code-block text |

### State layers (`color-mix()` overlays)

Use on any interactive element:

```css
.my-interactive {
  background-color: color-mix(in srgb, var(--color-primary) var(--state-hover), transparent);
}
```

| Token | Light | Dark |
| --- | --- | --- |
| `--state-hover` | 8 % | 10 % |
| `--state-focus` | 12 % | 14 % |
| `--state-pressed` | 12 % | 14 % |
| `--state-selected` | 16 % | 20 % |
| `--state-disabled-opacity` | `0.38` | `0.38` |

The `%state-layer` placeholder in `_Color.scss` composes the overlay for you:

```scss
.my-button { @extend %state-layer; --state-layer-color: var(--color-primary); }
```

### Dark mode strategy

`[data-theme="dark"]` (set by `js/theme.js`) remaps system tokens. No
component should carry its own `[data-theme="dark"]` selector — instead,
consume semantic tokens and let the root remapping do the work.

`@media (prefers-color-scheme: dark)` mirrors the same overrides via a shared
`@mixin dark-theme-tokens` so the explicit attribute and OS preference stay
in lockstep.

## Typography

`scss/_Typography.scss` defines the font stacks and fluid type scale.

| Stack | Use |
| --- | --- |
| Helvetica Neue → Hiragino Sans → BIZ UDPGothic → Yu Gothic Medium → Meiryo | Default body + headings |
| Yu Mincho → Hiragino Mincho | Mincho variant (`.mincho`) |
| Poppins | `design-font-en` accent — English-only display |
| SF Mono → Monaco → Menlo → Consolas | Code / monospaced (`--font-mono`) |

Headings use **`font-weight: 500`** and **negative `letter-spacing`**, not bold.
All headings are fluid via `clamp()`; bodies are fixed at 16px with
`line-height: 1.35`.

### The `design-font-en` accent

Single-use display style for English display accents — Poppins 500,
`--color-hotpink` (`#ff69b4`), with a dashed underline on `h1.design-font-en`.
Used sparingly.

## Spacing, radius, motion, elevation

- **Spacing** — 4px baseline. Scale: `--spacing-1` (4px) … `--spacing-16` (64px).
- **Radius** — `--radius-xs` 2px · `--radius-sm` 4px · `--radius-md` 8px ·
  `--radius-lg` 12px · `--radius-xl` 16px · `--radius-full` 9999px. Pill buttons
  use `--border-radius-all` (3rem) for the classic Asagiri silhouette.
- **Motion** — `--motion-duration-{instant|short|medium|long}` = 50 / 150 / 250 / 400 ms.
  Easings: `standard`, `emphasized`, `decelerate`, `accelerate`. Buttons lift
  `-1px` on hover. `prefers-reduced-motion: reduce` zeroes out all durations.
- **Elevation** — 6 levels (0–5). Each is a three-shadow composite
  (key / ambient / penumbra) where the shadow RGB is `--color-shadow` and opacity
  comes from `--shadow-key`, `--shadow-ambient`, `--shadow-penumbra`. Opacity
  values are elevated in dark mode for visibility.

## Iconography

All icons are inline SVG, `stroke="currentColor"`, `stroke-width: 2`,
`stroke-linecap: round`, `stroke-linejoin: round`. Recommended set: **Lucide**
(`https://unpkg.com/lucide@latest`). No icon fonts; no emoji.

## Voice & content

- **Tone** — technical, confident, quietly playful. Short benefit statements;
  no marketing fluff.
- **Case** — Title Case for English headings, sentence case for prose,
  kebab-case for CSS hooks, camelCase only in JS.
- **Pronouns** — imperative and direct. Japanese drops pronouns; English prefers
  "Click / Hover / Please" forms.
- **Emoji** — **never used** in UI copy. Unicode glyphs (`/`, `×`, `…`) only as
  separators or non-decorative punctuation.

## Consuming the tokens outside Sass

For projects that don't use a Sass pipeline:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/asagiri/css/tokens.css">
```

This gives you every `--color-*`, `--radius-*`, `--motion-*`, `--elevation-*`,
`--state-*`, `--global-component-*` token as pure CSS custom properties,
including the `[data-theme="dark"]` and `@media (prefers-color-scheme: dark)`
remappings.

Regenerate locally with `npm run build:tokens`.
